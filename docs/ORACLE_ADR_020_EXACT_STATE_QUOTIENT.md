# ADR-020 — Exact additive reward-state quotient and Small Points periodicity (iteration 25)
**Date:** 2026-11-02. **Status:** ACCEPTED AS EXACT RESEARCH ENGINE; NOT LIVE DEPLOYED.
**Binding:** North Star, ADR-007, ADR-010/011, ADR-014/015 and ADR-019. Target remains global expected FINAL Big Points with every future action chosen optimally across all seven categories and 28 turns.

## New exact Bellman equivalences (not a fitted value model)
1. For each sum-threshold category (4s,5s,6s,Choice), if capped accumulated sum already reaches threshold, its +2 Big Point reward is **secured**; if even the mathematically maximal remaining small scores cannot reach threshold, its +2 is **dead**. In both cases future category decisions and future small-score distributions are identical conditioned on all other state coordinates and remaining slots. Therefore normalize both secured and dead category progress to one sentinel, and add +2 to a separate state-value offset ONLY in the secured case. Pending-but-feasible thresholds retain exact sum.
2. Completed Straight (4/4 filled) has fixed +4 Big Points if all four valid, or 0 if scratched. Completed Full House similarly +3/0. Replace their now irrelevant intact flags by one sentinel and move already secured reward to additive offset. Before completion retain intact flag.
3. For every integer n>=250, the genuine bonus rule satisfies bonus(n+50)=bonus(n)+1. Since future small scores never decrease, canonicalize current totalSmall >=250 to 250+(totalSmall-250) mod 50, moving floor((totalSmall-250)/50) to the additive offset. Previous v21 only exploited this symmetry when >=450. Below 250 and for fully flat bonuses, retain original exact behavior.
4. Store Bellman W(s)-offset under a collision-free 64-bit mixed-radix canonical key. Both Bellman equations, all 252 dice histograms, all legal 210 hold variants, scoring rules, terminal reward and optimal adaptive future choices are UNCHANGED. Any two states under one key differ by a pathwise CONSTANT Big Point offset for every corresponding sequence of legal actions and dice; hence max over optimal policies respects exactly the same difference.

## Independent measured accuracy and scale
- Seven 10-turn native C++ head-to-head tests, 509 distinct current full action values, original V21 vs V25: **49.6–67.3% fewer W(s) states**, arithmetic average **58.3%**, **2.01–3.20× faster** on same Linux/container/compiler flags. Maximum root Q value difference <2.5e-14 BP.
- Separate extended root tests compared 575 legal actions including entire 461-value turn policy table and two legal derived scorecards. Three synthetic offset identities for secured category (+2), completed straight (+4), and small-bonus shift of +50 (+1) matched to ~1e-14 BP.
- New independently generated **11-turn** score-only root: original V21 **1,321,603** states / **18.54 sec**, V25 **412,698** / **6.24 sec**. V21 failed at prior 1m-state budget while V25 completed.
- New **11-turn two-reroll** root with all 28 legal actions: V21 **1,489,864** states / **22.38 sec**, V25 **471,764** states / **7.03 sec**. **68.3% fewer states**, ~**3.18× speedup**. All 28 exact Q values reproduced, max absolute difference 8.9e-15 BP. Optimal: hold one 5 and one 6, expected final BP 9.5238386427.
- Ablation at 10-turn root (baseline 300,555 W states): periodic bonus alone 171,327; secured/dead fixed-category quotient + completed categories alone 215,393; combined 111,414. On another 11-turn root, completed category quotient improves combined 142,126 to 127,823. Thus more than superficial key formatting; this is genuine exact-state merger.
- A separate 12-turn score-only root exceeded 900k-state budget even with V25; no new exact 12/20/28-turn certification is asserted.
- ZIP extracted into fresh directory, both engines compiled independently and smoke full-action cross-check PASSED. More comprehensive suites were run in research work directory. Some long repeated regressions hit environment time limit and are not claimed complete. C++ uses Float64, not formally outward-rounded machine-checked arithmetic. Not benchmarked Safari/iPhone.
